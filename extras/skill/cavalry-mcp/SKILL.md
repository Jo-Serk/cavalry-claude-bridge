# Работа с Cavalry через MCP-мост

Cavalry работает на компьютере пользователя, а связь идёт через локальный MCP-сервер и плагин Stallion. Всё, что известно о сцене, приходит через инструменты `cavalry_*`. Если их нет, скажи пользователю проверить, что Stallion запущен (Scripts > Stallion, «Listening on 127.0.0.1:8080») и что Claude Desktop перезапущен после сборки сервера.

## Порядок работы

1. Перед правками вызови `cavalry_get_scene`. Он показывает иерархию, изменённые атрибуты, выражения, анимацию и связи между узлами. Не гадай по памяти, что лежит в сцене: пользователь мог поменять её руками.
2. Правь небольшими шагами. Связи делай через `cavalry_connect` (сам создаёт слоты массива, заменяет занятый вход и проверяет результат), тип распределения Duplicator меняй через `cavalry_set_distribution`. Всё остальное делай через `cavalry_execute_script`; если в нём вызываешь `api.connect` напрямую, проверяй результат через `api.getInConnection`, потому что `connect` при неудаче ничего не сообщает.
3. Не угадывай имена функций API. Ищи их через `cavalry_api_search` (регулярное выражение по именам `api.*` и типам слоёв).
4. После правок снова вызови `cavalry_get_scene` и посмотри картинку через `cavalry_render_frame`.
5. Перед удалением слоёв, подменой сцены или массовыми правками, о которых пользователь не просил, предупреди и попроси сохранить сцену: скрипты выполняются сразу.

## Как писать скрипты

- Результатом становится значение последнего выражения. Чтобы использовать `return`, оберни код в `(function(){ ... return x; })();`.
- Ошибки API приходят строками, а не объектами `Error`.
- Если вывод `console.log` не возвращается, значит стоит старая версия моста: возвращай данные через результат выражения.
- Значение `undefined` мост показывает как «Success» или «no value». Это не значит, что скрипт что-то сделал.

## Чего ты не видишь

- Интерфейс Cavalry: меню, открытые панели, выбор в выпадающих списках. Для этого нужен скриншот от пользователя.
- Подписи значений у обычных enum-атрибутов: `getAttributeDefinition(...).enumValues` бывает неполным или пустым. Если числу нужна подпись, сверься с интерфейсом или попроси скриншот. Тип распределения у Duplicator к этому не относится: он меняется через `api.setGenerator`, старый атрибут `generator.distributionMode` для этого не годится (см. справочник).
- Картинка от `cavalry_render_frame` показывает кадр композиции, а не вьюпорт. Второй параметр `api.renderPNGFrame` задаётся в процентах (100 = полный размер).

## Справочник по API

Перед созданием узлов, подключениями, работой с Duplicator и Random прочитай `references/api-facts.md`: там проверенные на живой сцене имена функций, формы значений и типичные ловушки.

## Насколько подробно ты видишь атрибуты без рендера

- По каждому атрибуту: имя, тип, текущее значение, значение по умолчанию, менялось ли оно (`isAttrDefault`), границы и шаг (`numericInfo`: hardMin, softMin, softMax, step), выражения и анимация.
- Связи между узлами в обе стороны, иерархия, выделение и текущий кадр (всё это есть в `cavalry_get_scene`).
- Габариты геометрии через `api.getBoundingBox(id, true)`: по ним можно проверять раскладку числами (например, размах 428×371 у трёх клонов на окружности).
- Позиции отдельных клонов Duplicator и то, как кадр выглядит (перекрытия, впечатление от цвета), по данным не видны. Для этого используй `cavalry_render_frame`.

## Типичные ловушки

- После удаления узла-драйвера (Random и т. п.) на атрибуте остаётся его последнее значение. Например, у `shapePosition` дубликатора остаётся сдвиг. Сбрось атрибут через `api.set(id, { attr: значение_по_умолчанию })` и проверь `api.isAttrDefault`.
- Неизвестное имя типа в `api.setGenerator` не даёт ошибки. `cavalry_set_distribution` это проверяет, а при ручном вызове сверяйся с `api.getCurrentGeneratorType`.
- Временные узлы, которые ты создавал для проверки, удаляй сам и возвращай сцену в исходное состояние.
